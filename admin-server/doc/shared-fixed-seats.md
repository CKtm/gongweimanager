# 共享工作室与固定工位导师归属

## 业务规则

- 工作室可以共享；gw_workstation.mentor_id 是固定工位归属的唯一依据。
- 管理员在小程序“管理员工作台 → 基础管理 → 工位与布局”单个编辑，或勾选工位后使用“划分导师”批量维护。单次最多200个，失败时整批回滚。
- 使用中、回收中的工位不能更换导师，应先正常释放。空闲或停用工位可以更换或解除归属。流动工位不能设置导师。
- 导师只能把自己名下的固定工位分配给自己的学生，一个学生只能有一个有效工位；导师直接收回自己的固定工位后立即释放。
- 流动申请提交、导师审批、管理员审批和分配均按导师在所有正常房间中的空闲固定工位数量校验。
- 房间接口的mentorName为工位导师姓名汇总；mentorId仅在房间只有一个工位归属导师时返回，否则为null。不要根据房间mentorId校验工位操作权限。
- 导师不再申请工作室或固定工位。所有固定工位由管理员直接划分给导师，导师再分配给自己的学生。旧申请仅供查询，未处理的申请标记为已取消。
- 卫生检查继续支持学生工位和工作室整体评分。

## 升级

1. 备份MySQL数据库。
2. 在业务数据库执行 sql/gongwei_shared_fixed_seats_upgrade.sql。
3. 执行 sql/gongwei_admin_direct_fixed_seats_upgrade.sql 停用旧申请流程并取消未处理申请。
4. 重启后端并重新编译小程序。PC后台如需使用，同步更新前端。

升级首次新增工位mentor_id字段，使用中座位优先继承学生导师，其他固定工位继承原工作室导师。原占用和卫生记录保持不变。重复执行脚本不会覆盖已调整的工位归属。gw_room.mentor_id旧列仅保留用于历史溯源，不再作为业务归属来源。

当前本机已备份并执行升级。新环境须手动执行上述迁移；全新建库则使用更新后的gongwei_manager.sql。
