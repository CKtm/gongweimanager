# 学生记录、申诉、消息与定时处罚

本次修改在本地项目完成，未发布到线上、未推送 GitHub。小程序继续使用现有本地接口配置。

## 已实现的业务

- 学生：个人中心 →「卫生评分、处罚与申诉」，查看本人已核实或已归档的学生座位评分、处罚历史，针对具体记录提交申诉。
- 导师：工作台 →「学生申诉」初审本人学生的申诉；通过后进入管理员终审，驳回则结束。可查看学生处罚记录。
- 管理员：小程序工作台的「学生申诉」或 PC「处罚与申诉」终审。评分申诉通过时必须填写 0～100 的调整后分数；保留原分数、意见及调整后分数。处罚申诉通过时解除对应处罚。
- 导师：分配工位 →「批量分配」，勾选学生，为每人选择自己的空闲固定工位，选择起止日期后整批分配。禁止重复学生、重复座位。任何一项失败时，整批占用、状态和消息全部撤销。
- 导师：团队学生卡片 →「使用记录」，查看该学生当前及历史工位、使用期限、分配时间与结束时间。
- 管理员：单个或批量停用工位必须填写处罚原因和截止日期/时间。停用保留学生占用和绑定；管理员可提前恢复，也可在处罚记录中调整截止时间。
- 系统：后端运行时，每 30 秒检查到期处罚。恢复前核对原学生与原分配记录；收回、重分配、逻辑删除后不会误恢复。房间不可用时通知管理员并等待房间可用后重试。重启后会补处理已经到期的处罚。
- 消息中心：个人中心、导师和管理员工作台均有入口和未读数，支持逐条阅读、全部标为已读。通知覆盖分配/收回、流动申请与退还进度、检查任务下发/提交、已核实学生评分、处罚变化和申诉审核。

消息目前是系统内通知，需要进入小程序查看；尚未接入微信订阅消息。截止时间按北京时间填写。

## 数据与权限

- 新增 `gw_penalty`、`gw_message`、`gw_appeal`，给卫生检查记录新增学生和分配记录快照。
- 学生只能查询、申诉本人的记录；导师只能查看和初审自己的学生；卫生检查员只能访问自己的消息，不能访问学生处罚与申诉列表；管理员终审不能跳过导师初审。
- 学生座位评分在提交检查记录时由服务端保存当时学生和分配关系，后续更换使用人不会转移旧评分。工作室整体评分不计入某一个学生的个人评分。
- 旧评分只有能明确匹配原分配时间段时才回填学生信息；无法确认的旧记录继续保留在检查台账，不向学生推测归属。
- 旧的停用座位生成历史处罚记录，截止时间留空，须管理员补充，不自动随意解除。
- 逻辑删除和历史分配规则保持原有行为。
